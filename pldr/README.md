# pldr/: the patch-loader

The DigitDia Evolution bootloader has a card file it runs **from RAM without flashing**: `FWFS601T.BIN` in the root
of a FAT32 card. (Its board init renames Novatek's generic `FW96660T.BIN` to `FWFS601T.BIN`; `FWFS601A.BIN` and
`LDFS601A.BIN` are the names that **write** flash.) The patch-loader is a small program in that slot. It contains
only our code, the patch words and some hashes.

## What it does at every power-on

| step | how | if it fails |
|---|---|---|
| 0. relocate | `entry.S` copies the image from 0x80000000 to 0x8e000000 (own SYNCI cache maintenance) | — |
| 1. check the bootloader | FNV-1a hashes of the 6 routines it calls ([sig.h](sig.h)) | stops: the scanner doesn't start; remove the card |
| 2. read the firmware | bootloader storage init `0x8ff0d984`, **read** `0x8ff0d408` (block 8 = flash 0x8000), deinit `0x8ff0ca88`. The erase/program routine is never used | stops |
| 3. unpack | bootloader decompressor `0x8ff0815c` → 0x80000000 | — |
| 4. recognise | unpacked size + 32-bit word sum ([patches.h](patches.h)) = stock firmware 2.0? | **boots it unpatched** |
| 5. patch | writes the 58 words from `patches.h` (includes the EXIF tag and the fixed image checksum) | — |
| 6. hand over | restores the bootloader's handoff block at 0x80000080 with boot flags *normal flash boot* (card bit 4 → flash bit 8), firmware size at +0x98 | — |
| 7. start | bootloader D-cache flush `0x8ff08110`, I-cache invalidate `0x8ff080b4`, jump to `*(0x80000000)` | — |

Because of step 6, the firmware behaves exactly as after a normal boot: it loads and saves settings, and file
numbering continues. A full firmware image run from the card needs an extra patch for that (`src/patch_noT.py`).

## Memory use while it runs

| range | use |
|---|---|
| 0x80000000–0x8159deb4 | the firmware being unpacked (22.6 MB) |
| 0x8c000000– | compressed firmware read from flash (3.4 MB) |
| 0x8e000000– | the patch-loader itself, stack top 0x8e080000 |
| 0x8ff00000–0x8ff0f8e4 | the bootloader (stage 1, stage-1 tail at 0x8ff08000, body at 0x8ff09000, its stack) |

## Files

| file | what |
|---|---|
| `entry.S` | entry at load address 0x80000100: copy to 0x8e000000, cache maintenance, jump to `pldr_main` |
| `pldr.c` | the steps above |
| `pldr.ld` | linker script (linked for 0x8e000000; the first 0x100 bytes are the image header) |
| `patches.h` | generated by `make_pldr.py --regen`: stock fingerprint + patch offsets/values |
| `sig.h` | generated by `tools/gen_sig.py` from a flash dump: hashes of the bootloader routines |

## Testing

`python make_pldr.py --dump <your flash dump>` runs `tools/emu_pldr.py` (Unicorn emulator, 74K CPU with DSP) with
the real bootloader code from the dump:
1. the stock flash gives exactly the expected patched image + handoff, and the firmware entry is reached
2. altered firmware boots unpatched
3. an altered bootloader is refused before any bootloader routine runs
